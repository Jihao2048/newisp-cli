# STC 各系列可选 IRC 频率表

本文按官方 ISP 下载软件（AiCube-ISP）下拉菜单，逐系列整理**内部 IRC
可选频率**。每个系列一张独立表，互不通用。

用途：`newisp` 写入选项字节时，目标频率必须是该系列菜单里真实存在的档位。
写一个芯片做不到的频率不会让编译或烧录报错，只会让程序以未知速度运行，
症状是"时序微妙地不对"，很难排查。

标称单位为 MHz，内部以 Hz 存储。截图见 `频率表/` 目录。

### 易混点

- **STC32G144K246 没有 27.000**，而 8051U / 8H / 8A / 8G / 15 都有。
- **8H 末尾是 45.1584，8A 末尾是 45.000**：两张表的唯一差别就是最后一档，
  相差 0.35%，不能互相替代。
  - 命名陷阱：**STC8A8K 前缀不等于 8H 硅片**。芯片表里
    `STC8A8K64S4A12`、`STC8A8K64D4`、`STC8A2K64D4` 都是 8A，
    末尾走 45.000；家谱判断不能只看前缀。
- 8051U 与 8H 的 16 档全部相同，但仍是两张独立表，不要合并成一个常量。
- 8G 与 15 的 12 档全部相同。
- **44.2368 在厂商菜单里，但当前不可选**：没有 trim 三元组；
  且社区实测该频率下 USB 无法枚举（见文末「未收录的档位」）。

## 不可调频率的系列

### STC10 / STC11 / STC12

没有频率菜单，取而代之的是**时钟源选择**：内部 IRC 或外部晶振。
写频率选项对这类芯片没有意义，工具应在选项阶段拒绝写入，只写时钟源字段。

### STC89 / STC90

固定使用**外部晶振**，频率由板上晶振决定，下载软件不提供 IRC 档位。

## 实现要点

1. **每系列一张表**（`chip_logic.h` 里的 `kFreqTableStc8G`、
   `kFreqTableStc15`、`kFreqTableStc32G144K246`、`kFreqTableStc8051U`、
   `kFreqTableStc8H`、`kFreqTableStc8A`），不要合并成全局表。
   STC32G144K246 的 60 MHz 档在 8051U / 8H 上不存在，写进去会得到非法
   trim。`FrequencyMenuFor(chipName)` 是唯一的查表入口。2. **上限按系列 clamp**：全局取 60 MHz 会让 8H 也能选 60 MHz。
   同理 8H 与 8A 的上限值不同（45.1584 与 45.000）。
   家用判断顺序在 `FrequencyMenuFor` 里写死，8A 必须排在 8H 兜底之前。
3. **按成员判定，不是区间判定**：`IsFrequencyInMenu` 只认表里的值。
   45.100 落在 8H 区间内但不是档位，`newisp` 会拒绝而不是四舍五入到
   45.1584——写选项字节时没有对应的 trim。
4. **Hz 为整数存储**：所有档位乘以 1e6 后都是整数，无舍入误差。
5. **选项字节里频率是 24 位定点数**（单位 1/256 Hz），`count = freq / 256`
   取整。整 MHz 档位并不总能整除：6、27、30、35、45 MHz 这 5 个档位会留下
   余数，向下取整带来的误差最大为 21 ppm（6 MHz，128 Hz），其余不超过
   7 ppm，远小于 IRC 自身 ±0.3% 的精度。例：60 MHz → 234375（整除），
   45.1584 MHz → 176400（整除），5.5296 MHz → 21600（整除）；
   6 MHz → 23437，余 128 Hz。
6. 每个档位需要对应的 **trim 三元组**（trim / range / divider），
   STC32G144K246 与 AI8051U 的 trim 表互不通用，不能互相借用。
   菜单里有、trim 表里没有的档位会被 `ResolveFrequency` 拒绝并说明原因
   （`HasTrimFor`）；`test_chip_logic.cpp` 会检查两张表是否一致。
7. **不在菜单里的档位不写**。以前 `ClampFrequency` 会把超上限的值夹到
   上限，那会把「8H 上要 60 MHz」悄悄变成「45.1584 MHz」，烧录一个用户
   没要求的频率。现在只有**超出该系列上限**的请求才夹取并记录日志，
   其余一律拒绝。

## 未收录的档位与理由

| 档位 | 出现在 | 未收录原因 |
|---|---|---|
| 32.000 | STC32G144K246 | 无 trim 三元组 |
| 50.8032 | STC32G144K246 | 无 trim 三元组 |
| 44.2368 | 8051U / 8H / 8A / 8G / 15 | 无 trim 三元组；社区实测该频率下 USB 无法枚举 |

这三档都**在厂商菜单里**，列出来是为了让读者知道「厂商没给」和
「本工具还不能写」是两件事。补上实测 trim 后，加进对应表与 trim 表即可。

另外，46~50 MHz 超频档在所有系列里都不收录：它们不在任何厂商菜单中，
本仓库只有 46/47 MHz 实测通过，48 MHz 实测降频，49/50 MHz 是外推值。

## 与 STC32G 手册的关系

`STC32G-20261028.md` 第 7.5 节列出的出厂校准频率为：

```
22.1184  24  27  30  33.1776  35  36.864  40  44.2368  48
```

那份手册针对老 STC32G（12K128 等），上限 48 MHz，IRC 只有
6/10/27/44 MHz 四个频段。

**STC32G144K246** 有独立手册 `STC32G144K246-20261029.md`，是另一颗芯片：

- IRC 频段变为 **10/27/44/72 MHz** 四段
- HPLL 可编程：`HPLLDIV[3:0]` 提供 52~82 倍频，`HPLLPDIV[7:0]` 预分频，
  要求锁频基频固定 6 MHz
- 主时钟可来自 HPLL1/2 输出**或**其 2 分频
- 新增 `HPLL2`，以及 SPIn / PWMn / TFPU / I2Sn 独立时钟分频

正因为有 72 MHz 频段和可编程 HPLL，60 MHz 才成为可能。
